# 参考资料脱敏与通用化规范

## 原则

只迁移可复用的**结构、状态机、检查条件和失败处理**。不要迁移可识别的生产身份、私有配置、运行日志或业务数据。

## 替换表

| 原始信息类别 | 通用化写法 | 是否允许复制原值 |
| --- | --- | --- |
| 域名、URL、IP、外部端点 | `<EXTERNAL_SITE>`、`<SERVICE_ENDPOINT>` | 否 |
| 账号、邮箱、联系人、组织名 | `<OWNER_CONTACT>`、`<RESPONSIBLE_ROLE>` | 否 |
| 密码、令牌、密钥、cookie、认证头 | `<CONFIG_NAME>`；只说明获取方式和最小权限 | 绝不允许 |
| 绝对路径、机器名、用户目录 | `<PROJECT_ROOT>/<MODULE>` | 否 |
| 生产记录、用户数据、标识符、截图 | 聚合的状态、匿名样例或新建演示数据 | 否 |
| 真实部署命令与供应商绑定 | 平台无关的步骤、输入、输出、恢复条件 | 仅在已公开且确有必要时 |

## 安全导入流程

1. **分类**：把参考分为公开设计、通用工程模式、私有运行资料或敏感配置。后两类不得复制。
2. **抽象**：先写“输入 → 状态 → 输出 → 失败处理”，不要转贴原文、目录或命名。
3. **脱敏**：替换表中所有识别项必须替换；不确定时按敏感处理。
4. **重写**：用当前项目的语言、目录和验收条件重新表述，避免形成可反向定位来源的指纹。
5. **审查**：确认没有外部地址、账号、密钥、绝对路径、生产样本或未授权资产，再提交。

## 共享边界

- 共享代码、自动化和模板应以版本化工具或文档入口复用，不复制活动运行逻辑。
- 站点项目只保存自身的内容、设计方向、非敏感配置名和发布证据。
- 生成物、队列、缓存、下载物、浏览器 profile 和临时报告不作为模板来源。
- 任何外部写入都需要项目自己的授权、候选、证据与恢复路径；来自参考资料的“成功”不能构成当前项目的发布授权。
