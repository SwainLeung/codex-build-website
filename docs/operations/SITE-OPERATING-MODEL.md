# 通用站点运营模型

本模型将多站点参考中的工作方式重新表达为无身份信息的通用架构。它不包含真实站点、外部地址、账号、凭据、生产数据、绝对路径或供应商绑定。

## 五层模型

| 层 | 目标 | 最小项目资产 | 成功判据 |
| --- | --- | --- | --- |
| 站点契约 | 明确谁、为什么、以何种语气和视觉边界服务 | `SOUL.md`、`DESIGN.md`、站点画像模板 | 任何协作者可说明受众、主要行动和不做什么 |
| 内容与资产生命周期 | 让条目有可追溯状态 | 内容/资产记录模板 | 每个条目能指出当前状态、来源边界、下一门与负责人 |
| 质量门 | 将主观“好看/可发”拆成可检查事实 | `CHECKLIST.md`、自动检查 | 结构、体验、权利与技术检查有明确通过/失败结果 |
| 证据与恢复 | 将候选、发布和异常处理关联起来 | release record、构建产物标识 | 能找到基线、候选、预演证据和恢复路径 |
| 共享与本地边界 | 复用能力而不复制风险 | `tools/`、版本化模板、局部配置 | 共享逻辑通过入口复用；站点特有内容与编排留在项目内 |

## 通用生命周期

`intake → plan → draft → validate → review → release → observe → improve / quarantine`

- **intake**：记录用户问题、来源类别和约束，而不是直接采集生产数据。
- **plan**：决定条目的意图、结构、资产需要、成功信号和不确定项。
- **draft**：生成可审查候选；候选不等于发布内容。
- **validate**：运行结构、链接、可访问性、响应式、性能和来源/权利检查。
- **review**：由负责人检查剩余风险、例外项与证据完整性。
- **release**：登记不可变候选标识、环境、时间和恢复入口。
- **observe**：只收集与已定义成功信号有关的最小聚合数据。
- **improve / quarantine**：将通过验证的改进循环回计划；不确定、冲突或权利不明的内容隔离，不自动发布。

## 当前项目的最小落地

| 当前位置 | 对应层 | 补充动作 |
| --- | --- | --- |
| `SOUL.md` / `DESIGN.md` | 站点契约 | 分别维护编辑边界与视觉/交互边界，不把运行配置放入其中 |
| `docs/templates/SITE_PROFILE.example.yml` | 站点契约 | 从模板创建项目画像；只填公开、非敏感的事实 |
| `docs/templates/CONTENT_ASSET_RECORD.example.md` | 生命周期 | 为未来内容或媒体填写状态与来源边界 |
| `docs/CHECKLIST.md` | 质量门 | 在候选发布前完成手测与自动检查 |
| `docs/harness/releases/` | 证据与恢复 | 填写候选 SHA、预演与恢复责任 |
| `tools/` | 共享与本地边界 | 通过文档化入口复用工具；不复制运行时目录或环境文件 |
