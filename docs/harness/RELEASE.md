复制到 `docs/harness/releases/<版本>.md`，在首次预演前填写。使用项目的实际版本号，文件名中的斜线换为短横线；同版重试在同一记录追加批次和结果。预演、分批放量也可对应包的预发行渠道或静态站点的预览环境。

## 1. 核对本次候选版本

结论使用「待核验、通过、失败、不适用」。每个通过项填写负责人和可复核证据，证据须指向本次版本、提交或产物。G06、G07 没有相应变更时可填「不适用」，由负责人写明依据。证据缺失、候选产物改变或仍有失败项时，补证或重新核验后再作发布决定。

| ID | 要核对的事实 | 负责人 | 结论 | 证据 / 不适用依据 |
| --- | --- | --- | --- | --- |
| G01 | 需求与评审。Issue 的验收条件可逐条对应 PR，相关模块维护者已复核关键改动。 | | 待核验 | |
| G02 | 测试与构建。候选提交通过项目实际检查，记录 CI 运行链接、SHA、构建或适用的交付方式。 | | 待核验 | |
| G03 | 交付物与预演。记录候选产物，已在预览、测试环境或干净安装中复现关键用户操作，发布引用同一产物。 | | 待核验 | |
| G04 | 回滚准备。可找到上一稳定版、恢复操作人、操作入口、验证路径及最近有效的演练记录。 | | 待核验 | |
| G05 | 监控与发布责任。核对指标来源、观察时长、停放量阈值、值守人和通知方式。 | | 待核验 | |

## 2. 决定并执行

先写观察条件，再填写实测结果。阈值由目标项目按基线设定，例如可以观察关键操作的成功比例、连续失败次数或包安装成功率。写出统计分母、单位和观察窗口。请求量低的项目可用预先约定的人工冒烟次数和一组明确结果。

| 指标 / 用户操作 | 来源与查询入口 | 发布前基线 | 触发暂停或恢复的阈值 / 窗口 / 最低样本数 | 观察人 |
| --- | --- | --- | --- | --- |
| | | | | |

| 批次 / 环境 | 发布或放量入口 | 预期行为与冒烟步骤 | 时间（含时区）/ 执行人 | 运行链接 / 实测值 / 结论 |
| --- | --- | --- | --- | --- |
| 预演 | | | | |
| 首批或正式发布 | | | | |
| 后续放量（适用时） | | | | |

- **发布决定**　填写「发布」或「暂缓」，注明责任人、时间和门禁证据链接。Excel 的汇总可供核对，实际执行以本次决定为准。
- **执行步骤**　填写目标平台的真实工作流名、脚本路径或控制台操作与环境。部署使用上方登记的候选产物；将平台运行号、开始时间和冒烟证据追加到批次行。
- **异常处置**　达到阈值时立即暂停扩大范围。记录发现时间、受影响用户或批次、当前指标、执行人及决定。观察数据缺失时先恢复可观测性，再决定是否继续放量。

## 3. 恢复并验证

发布前填写恢复方案，异常发生后补写结果。依赖持久化数据的变更先核对新旧应用与当前数据结构的兼容性。备份恢复会影响备份后的写入，应明确补录或对账方法。

| 步骤 | 发布前填写 | 发生异常时填写 |
| --- | --- | --- |
| 停止扩散 | 暂停放量或关闭功能开关的入口、操作人 | 开始时间、范围和结果 |
| 选择恢复路径 | 切回上一稳定产物或前向修复，列平台入口、必要权限和可用时间 | 实际产物或修复 PR、操作人、平台运行号 |
| 处理不可逆数据 | 声明可逆性、写入冻结条件、备份及恢复演练；若无法安全降级，指定兼容版本与前向修复路径 | 决定与依据、数据影响和对账结果 |
| 确认恢复 | 复测关键操作、核对数据，并按同口径监测恢复窗口 | 冒烟结果、指标值、恢复时间、确认人 |

## 4. 收尾并开启下一轮

登记最终状态、标签、产物、发布时间和观察窗口结束时间。将已发生的用户可见变化记入 `docs/harness/CHANGELOG.md`；回滚或撤回保留该版记录，指明实际运行版本。将故障或未完成改进转为后续 Issue，标注负责人、验收标准、目标版本或复查日期。把发布单和复盘链接回填到工作簿本次版本及相应想法行。
