---
name: code-verification
description: 修改业务行为后，用项目原生命令验证本次改动与既有行为，形成可复现的 PR 证据。
---

读取 diff、适用指令、规格、项目卡和 CI 的真实命令。列出每个受影响的入口以及一个正常和一个失败输入。

1. 先运行与行为直接相关的测试，确认发现了预期用例。修复缺陷时尽可能在修复前复现失败，记录修复后对同一输入的结果。
2. 依照项目约定执行格式、lint、类型检查及全量测试/构建；共用校验入口为 `python3 scripts/harness.py check`。格式化只覆盖任务文件。
3. 首个失败保留命令、基线、关键输出和返回码。修复后重跑失败步骤与受影响的完整检查。测试断言应继续覆盖原有用户契约。
4. 按“验收编号｜命令/输入｜预期｜实际｜提交或工作树差异”交付。条件欠缺时列出具体缺口及下一步。
